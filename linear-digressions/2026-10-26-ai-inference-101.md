# AI Inference 101

> **Season 4 opener: inference — the step from frozen weights to tokens on your screen — has two
> regimes with two different bottlenecks.** Prefill reads the whole prompt in one parallel pass
> and is limited by compute. Decode produces one token at a time, reloads all model weights for
> each one, and is limited by memory bandwidth. Most of inference engineering is finding out
> which regime dominates and moving toward the point where memory feeds the processor exactly as
> fast as it can compute.

## Insights

1. **Why the season.** Inference is *"under-covered relative to how important it is"*: training
   gets the attention, but inference is what users touch.
2. **The visible clue.** After you paste an article and ask for a summary there is a pause, then
   the tokens flow. The pause is **prefill** (time to first token), the flow is **decode**
   (output tokens per second).
3. **Attention is what costs.** Each token has a query (what am I looking for), a key (what I am
   about) and a value (my content). Queries match keys; matching values reweight the token's
   meaning. Her analogy: at a conference your interest is the query, the talk titles are the
   keys, the talk content is the value, and you leave with a slightly changed understanding.
4. **Prefill is compute-bound.** All prompt tokens go through the weights in one large parallel
   matrix multiplication. A bigger processor helps.
5. **Decode is memory-bound.** *"Each time it creates one of those tokens, it has to read in the
   full weights of the model"* — heavy reads for one token, then again for the next. Higher
   memory bandwidth helps; this is the bandwidth-limited part of the **roofline model**.
6. **The sweet spot** is equilibrium: data arrives at the processor exactly as fast as it can
   compute — a factory whose supply matches its throughput.
7. **Three levers.** Long prompts push toward compute-bound; short prompts with many turns push
   toward memory-bound. Bigger models move more bytes (sometimes across several machines);
   that is why small models are fast. Hardware helps only on the lever that binds.
8. **Expensive hardware may disappoint.** A data-center node *"fell off the back of a truck"*
   might not speed up your local setup much, because processor capacity on chips has grown
   faster than memory bandwidth — so memory is often the bottleneck.
9. **The cliffhanger:** every token attends to every other token, so attention is n². *"N
   squared is poison."* How serving at scale escapes it is the next episode (KV cache).
