# The pivotal vote — a second opinion only pays where the vote is 4–3

The starting point is prior work (Kohli 2026): a panel of nine LLM judges carries about the
information of **two** independent ones, because their errors are correlated. The obvious fix
is a vote from a *different kind of evidence* — for code, actually executing part of the test
suite. Measured at scale, that fix changes the effective-vote count by **−0.04, 95 % CI
[−0.10, +0.02]** — nothing. Yet panel accuracy still improves. This paper explains the
apparent contradiction, and the explanation is arithmetic before it is empirical.

## The structural half (needs no data)

Replace one ballot in an odd-sized majority panel and the tally moves by at most one. So the
decision can only flip when the tally was already one vote from the boundary — margin
`m = |2s − k| = 1`, a **4–3** split on seven judges. **Proposition 1: on every query with
m ≥ 3, no choice of which judge to replace and no replacement value can change the outcome.**
Gain there is not "small". It is exactly zero, by construction, for any signal of any quality.

Corollary they draw out: an *aggregate* statistic averages a population that is 84 %
structurally unaffected and 16 % strongly affected. It can read "no effect" while a large
conditional effect is present — and the statistic is not wrong, it is answering a different
question.

Proposition 2 handles even panels, where ties break to "incorrect": now the pivotal set is
`s ∈ {k/2, k/2+1}`, which is **not symmetric in the margin**. On six judges, `s=4` and `s=2`
share |m| = 2 but only `s=4` can flip. Tested by re-deriving all 7 six-judge subsets of the
existing panel: `s=2` gain is **0.0000 in all 7**, exactly as predicted.

## The empirical half

Seven solver models × 463 problems (163 HumanEval+ / 300 MBPP+) = 3,241 candidates; 3–9
judges disjoint from the solvers, scoring without execution; signal = passing the first 20 %
of assertions.

| Config | Pivotal gain | Non-pivotal gain |
|---|---|---|
| HE+/MBPP+, k=7 | **+11.2 pp** [7.7, 14.7] | 0.0000 |
| HE+/MBPP+, k=9 | +10.4 pp [6.3, 14.4] | 0.0000 |
| LiveCodeBench, k=7 | **+23.3 pp** [18.0, 28.9] | 0.0000 |

Same pattern in all 56 dependent judge subsets (k=5: +7.9 to +14.3 pp; k=3: +6.5 to +16.1 pp;
non-pivotal exactly zero in every one). Pooled: n_eff 2.61 → 2.57 (not distinguishable from
zero) while overall accuracy rises +1.82 pp — and stratification locates that average
entirely on the 16.2 % pivotal subset.

Note what they do **not** claim: most errors are not pivotal. 199 of 569 are; 370 sit where
substitution provably cannot help.

## Three findings that cut against the paper's own recommendation

**1. Everything the panel does is beaten by doing less (Table 7).**

| Policy | Verifier calls | Accuracy |
|---|---|---|
| Panel only | 0 % | 82.44 % |
| **Best single judge** | 0 % | **87.16 %** |
| **Signal only** (just run the tests) | 100 % | **87.60 %** |
| Gate + majority-side replacement | 16.2 % | 85.62 % |

The best policy involving the seven-judge panel loses to the cheap deterministic check alone
by **2 pp**, and to one well-chosen judge by 1.5 pp. The authors state this plainly and make
their recommendation conditional: gating "is relevant only when a panel must be retained" —
for audit, multi-provider governance, or tolerance to one judge's outage — and they
explicitly **do not test** those benefits. Read without §6, the abstract's "raises overall
accuracy from 82.44 % to 85.62 %" sounds like a win; it is a smaller loss.

**2. The matched-accuracy permutation control says the signal is *worse* than a coin of equal
accuracy.** 2,000 synthetic signals with identical overall accuracy but randomly relocated
errors gain **+14.6 pp** on pivotal queries, 95 % range [13.1, 16.0]. The real execution
signal gains **+11.2 pp** — below the entire range. So its errors are *not* independent of
the panel's: both degrade on the same hard queries (panel accuracy 82.4 % → 62.1 % pivotal;
signal 87.6 % → 81.7 %). The authors accept this and downgrade their own claim to a
descriptive mechanism, not an independence result.

**3. The economics are inverted for this signal, and they say so.** Sandboxed execution takes
**49 ms**; one judge call takes **5.72 s** — 117× more. Gating saves calls to the thing that
is already ~100× cheaper than the machinery it is protecting. "Gating matters economically
when the verifier is expensive, not for this specific signal."

## Why panels fail exactly where it matters

Near the margin the panel's errors are not symmetric: **false negatives (correct code voted
incorrect) rise 7.5 % → 33.7 % — 4.5×** — while false positives rise only 1.4× (39.1 % →
53.6 %). Part of that is compositional. Judge quality spread is enormous:

| Judge | Reject rate | Accuracy | MCC |
|---|---|---|---|
| GLM-5-Turbo | 10.5 % | 87.2 % | 0.541 |
| Doubao-Seed-1.6 | 52.6 % | 58.5 % | 0.253 |

**And raw accuracy is a trap here: it correlates with reject rate at r = −0.99, because the
operational label is 80.4 % "correct" — leniency is rewarded almost by construction.**
Base-rate-robust measures shrink but do not erase the gap (balanced accuracy r = −0.61, MCC
r = −0.85). This panel holds more strict, low-MCC judges than lenient ones, so where the vote
is close enough for idiosyncrasy to decide, the panel inherits their shared error: false
rejection. Their cheap prophylactic: **confusion matrix + MCC on a calibration sample before
deployment**, not accuracy.

The worked example is the whole argument in one paragraph. On HumanEval 83 a correct closed
form `18*(10**(n-2))` passes the full suite; the panel splits 4–3 against it because one
judge offers a confident, elaborate, wrong derivation. The 20 %-coverage signal, which does
no reasoning at all, returns CORRECT and flips it: *an elaborate, confident, incorrect
derivation is exactly as persuasive to a plausibility-reasoning judge as a correct one — a
failure mode execution is immune to by construction.*

Stated limits: the signal is a **nested subset** of the operational label, so it has one-sided
errors by design and its complementarity may not transfer to independent or abstaining
verifiers; the accuracy sweep spans only 87.4–88.7 %; the 56 subsets are dependent, not
replications; replacement-rule comparisons are post-hoc on the discovery set; all benchmarks
are code.

**→ hier:** this repo runs actor/critic pairs everywhere (`copywriting-critic`,
`webdesign-critic`, `python-backend-critic`, …) on the same intuition the paper attacks.
Four transfers, in order of what they would change:

1. **Run the deterministic check alone before assembling any panel.** Signal-only beat every
   panel policy tested. Locally that means: the test suite, the `grep`, the API call, the
   `git ls-files -s` — the thing with no opinion. My repeated finding that a *measurement*
   beat a *judgement* ([[unrunnable check]], [[absence test]], [[proof with numbers]]) is the
   same result arriving from the other side.
2. **Score the critics before trusting them, and never on raw accuracy.** With a base rate
   where most things are fine, a lenient critic scores well by saying yes — exactly the shape
   of a green check that never fails. Reject rate + MCC on a calibration sample is a cheap
   pre-flight. [[coverage || loophole]]
3. **When two sources agree, a third adds nothing; spend only on the split.** Not a new idea
   here (it echoes the swarm paper's "ask three models once before asking one model three
   times"), but this paper makes it exact: outside the one-vote margin the gain is
   *provably* zero, not merely small. Where the economics differ — my deterministic checks
   are the cheap side, the LLM call is the expensive one — the gate flips: run the check
   always, convene the panel only on disagreement.
4. **The permutation control is the method worth stealing.** Before believing a second
   opinion helped, ask whether a *random* second opinion of the same accuracy would have
   helped more. Here it would have — by 3.4 pp. That test is cheap and it is the difference
   between "the extra source is independent" and "the extra source fails on the same hard
   cases".
