# ConsistencyGate — check the fact at write time, not at read time

The failure mode, named precisely: **memory contamination**. A hallucinated fact written once
is read back many times, so a write-time error becomes a false premise for every later step.
The paper's sharpest argument is that this cannot be fixed downstream — it is *not* a
retrieval problem (an oracle retriever still surfaces the bad fact), *not* a capacity problem
(eviction ranks on utility, not truth), and *not* covered by existing admission policies:
"Alice graduated in 2015" (context says 2012) is exactly as relevant, novel and recent as the
correct fact. **Utility-based admission is structurally blind to correctness.**

## Mechanism

Before committing candidate fact `m` extracted from context `c`, query the LLM **K times**
with a soft verification prompt scoring support on a continuous 0–1 scale; admit if the mean
≥ τ. Recommended default **τ = 0.7, K = 5**. Model-agnostic, no fine-tuning. Two variants: a
single-forward-pass **LogProb** version (softmax over `log p(yes)` / `log p(no)`), and an
adaptive τ that scales with memory occupancy for when tuning is impossible.

Three benchmarks, all released, all at a controlled 50 % contamination rate: **MemContam**
(synthetic, 1 000 correct + 1 000 corrupted facts over 200 contexts), **LoCoMo-Contam** and
**MSC-Contam** (real long-term conversations with one concrete detail changed per probe fact;
50 and 41 probe pairs).

## Numbers (Qwen2.5-32B, Table 1)

| Benchmark | ρ WriteAll → Gate | Precision | Recall | QA F1 |
|---|---|---|---|---|
| MemContam | 50.0 → **1.2 %** | 0.500 → 0.988 | 1.00 | 0.474 → 0.840 |
| LoCoMo-Contam | 50.0 → **34.1 %** | 0.500 → 0.659 | **0.58** | insensitive |
| MSC-Contam | 50.0 → **36.7 %** | 0.500 → 0.633 | 0.93 | insensitive |
| LoCoMo (clean) | — | — | — | 0.271 → 0.267 (−1.5 %) |

A **Random baseline** admitting at the same rate does *not* improve over WriteAll (ρ 47.7 on
LoCoMo-Contam, clean F1 0.227) — so the gain comes from correctness filtering, not from
having a smaller memory. Across four backbones, real-data reductions span **20 % (Llama4-Scout
on MSC) to 62 % (Gemma4-31B and Llama-3.3-70B on LoCoMo)**; verifier capability is the
dominant spread.

**K barely matters, τ does.** K=1 → K=10 buys 1–2 precision points (682 ms vs 75 ms per
fact). Raising τ 0.3 → 0.7 moves Qwen 0.931 → 0.988, Scout 0.860 → 0.997; τ=0.9 matches τ=0.7
within noise, which identifies 0.7 as the actual decision boundary rather than a tuned value.

**LogProb: 23–28 ms vs 264–363 ms at K=5 (12–14× faster)** — and it wins on MemContam but
**loses to soft scoring on LoCoMo-Contam on every backbone.** The authors explain it
("bimodality of yes/no support"): short structured contexts saturate the yes/no logits so one
pass suffices; long conversational contexts have continuous score distributions that only
K-sample averaging recovers.

## What the paper itself disowns

- **MemContam's 1.2 % is not a deployment number** and they say so: corruption strategy (d)
  appends a literal contradicting clause, and the verifier shares a model family with the
  corpus generator. They call it an internal-consistency upper bound.
- **On the two real benchmarks the QA F1 column is meaningless** — correct probe facts are
  pre-seeded into memory by construction, so downstream QA is insensitive to gate decisions.
  The only real signals there are ρ and precision.
- **The price is 42 % of correct facts rejected** (recall 0.58 on LoCoMo-Contam, systematic
  across all four backbones at 0.52–0.68). Cause: LoCoMo facts are implicit or distributed
  across many turns, and the verifier prompt demands explicit support. Pre-seeding hides this
  cost in the paper; it is permanent in deployment.
- Consistency is a **proxy** for correctness. Where a fact needs world knowledge the context
  does not carry, the verifier votes yes for plausible-but-wrong claims.

Stated operating regime: **document-grounded or tool-grounded memory writes, not emergent
multi-turn conversational memory.**

**→ hier:** tempting to read as "gate what enters `MEMORY.md`" — but the paper's own recall
number argues against exactly that. A session learning is implicit and distributed over a
whole run: it is the LoCoMo shape, where the gate throws away two of five true facts. Where
it *does* fit here is the other kind of write: a number extracted from an API response, an
invoice, a store page — short, structured, single source. That is the MemContam shape, and
there the cheap LogProb variant is the one to use.
