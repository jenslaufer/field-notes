# The counter-example the reading list needed: the dumb tool causes the hallucination

Every other paper in section 4 says the same thing — put a deterministic check in front of the
model. This one runs the same experiment and gets the opposite sign. **The deterministic
constraint here is a JSON schema, and switching it on takes GPT-5.5 from 2 % fabrication to
100 %.** Nothing else changes: same document, same question, same model.

The design is an *Abstention-Affordance Ladder*, three rungs over a fixed input:

| rung | format | is abstention available? |
|---|---|---|
| 1 `freetext` | 2–4 sentences of prose | fully |
| 2 `json_esc` | every field admits `insufficient_evidence` / `null` | yes, but must be chosen |
| 3 `json_req` | required sentiment enum, min-count array, required quote | **no slot for it** |

The inputs are *unanswerable by construction*: a viral post that carries 12,400 likes and 870
reply **counts** but no reply **text**; a support ticket whose body reads "call audio not
transcribed". Any concrete value in those fields is a fabrication by construction, so scoring is
code, not a judge. That is the design decision that makes the paper hard to argue with — the
headline metrics never pass through an LLM.

## The matrix (E3, n = 40 per cell)

| model | freetext | json_esc | json_req (CFR) |
|---|---|---|---|
| qwen3.5 0.8B / 2B, llama3.2 3B, qwen2.5 7B | 98–100 | 100 | **100** |
| mistral 7B | 82 | 100 | **100** |
| llama3.1 8B | 95 | 100 | **100** |
| phi-4 14B | 92 | 98 | **100** |
| gemma4 e4B | 65 | 92 | **100** |
| gemma4 26B | 88 | 60 | **100** |
| Haiku 4.5 | 55 | 58 | 0 (*refuses* 40/40) |
| Sonnet 4.6 | 98 | 90 | 90 |
| Opus 4.8 | 0 | 9 | 13 (*refuses* 39/53) |
| GPT-5.5 | 2 | 0 | **100** |

Ten of thirteen models sit at 100 % in the right-hand column. The three that do not are not
better behaved — **they break the schema instead.** The paper prices that honestly and calls it
the *refusal tax*: prose where JSON was demanded is a crash to a production parser, not a
conscience. Across the whole matrix **exactly one configuration reaches 0 % fabrication with 0 %
format violations: a frontier model with an escape-hatch schema.** Every other cell pays in fake
data or in a broken pipeline.

## The measurement that settles it

The obvious objection — a *prompted* schema measures cooperation, so maybe the model would refuse
if it really meant it — is closed in §4.4 with grammar-constrained decoding, where a prose refusal
is not a reachable output and `insufficient_evidence` **is a legal token in the grammar, one
sample away**.

Result across 203 non-empty enforced trials, five open models:

- escape emitted on `sentiment`: **0**
- escape emitted on `main_themes`: **0**
- escape emitted on `representative_reaction`: **0**
- escape emitted on `controversy_level`: **12**

The first three fields are the ones whose values constitute the fabrication. The fourth is the one
where escaping concedes nothing, because the rest of the object already carries a full answer. A
typical output declares sentiment "positive", lists three themes, quotes a reaction nobody wrote —
and then reports controversy as `insufficient_evidence`.

**They can emit the token. They spend it only where it costs them nothing.** That is not a
salience or reachability failure, and it is the sharpest single result in this reading list.

## Where I would not let the paper stand

**Finding 3 compares numbers from two different task framings.** "The schema outranks the
instruction" rests on: an anti-fabrication system instruction cuts free-text fabrication 39 % → 4 %,
but does nothing under `json_req`. The 39 % → 4 % is explicitly "in our earlier task framing" —
i.e. not the same items as the schema arm. The schema arm itself is **n = 10 per model**. At that n,
"rescues phi-4 completely (100 % → 0 %)" has a Wilson upper bound near 28 %. The finding is
probably right — the GPT-5.5 100 % → 100 % is a genuine ceiling-to-ceiling null — but the
quantified contrast in the abstract is not a like-for-like measurement.

**"Within a single model family" is doing more work than it can carry.** Haiku 4.5, Sonnet 4.6 and
Opus 4.8 are three separately trained models with three different version numbers, months apart —
not a parameter sweep of one recipe. So the striking small-refuses / mid-fabricates /
large-refuses pattern cannot separate scale from training run. The paper's own careful sentence is
the defensible one ("it is not parameter count, and it is not recency"); the abstract's framing
invites a scale reading the data cannot support.

**The ladder is not monotone, and the paper only discusses the model where it is.** Haiku goes
55 → 58 → **0**; gemma4 26B goes 88 → **60** → 100. For those two, adding the escape hatch made
things *worse* than plain prose. Only GPT-5.5's clean 2 → 0 → 100 flip is narrated. The
non-monotone cells are printed but not explained.

**Credit where it is due:** gemma4 e4B is excluded from the enforced-decoding table because its
constrained decoder returns empty output on 35 of 40 trials — and the author verifies this is a
grammar-compatibility artifact by checking the *answerable* control threads, where the correct
answer is concrete JSON and it also comes back empty. That is a broken instrument handled
correctly, in public: the tool broke, and the author declined to score that as model behaviour.

## How this squares with Calibration Floor

[`2608.04355`](2608.04355-calibration-floor.md) points one way: force the output instead of
parsing it — schema instead of regex. Calibration Floor's evidence for that is solid: a median 71 % of measured "self-correction" was a regex failing to
find an answer. **PhantomFill is the other half of the same coin.** Forcing the output fixes the
*measurement* and creates a *fabrication*, in exactly the cell where the honest answer is "no
evidence".

The two results reconcile into one rule rather than a contradiction:

> **Force the format, but never force a value.** Every required closed-vocabulary field needs a
> legal escape, and the escape must be measured, not assumed — because the models spend it only
> where it is free.

Two cheap consequences follow from the paper's own recommendations: a **schema linter** that
flags every required closed-vocabulary field lacking an escape — deterministic, a check with no
opinion in it; and **measure EUR before trusting the escape** — frontier models take the exit,
while the open models in Table 1 fabricate at 60–100 % with the escape *sitting in the schema*.

Strings can carry a hedge; enums and min-count arrays cannot. GPT-5.5 fabricated a required
sentiment enum 20/20 and invented a customer quote 0/20 — it wrote "no quote available" into the
free string. **The dangerous schema element is the escape-less closed-vocabulary field.**

## The one design idea worth stealing

Opus 4.8, given an impossible required schema, returned valid JSON *of its own design*:
`{"status": "insufficient_data", "reason": ...}`. The author names this **structured refusal** and
argues it is what the required-field rung should elicit — the pipeline still breaks, but it breaks
legibly, with a parseable reason instead of a stack trace or a lie. That is a distinction
expressed as a return type: *unreadable is not false, and it needs its own branch.*
