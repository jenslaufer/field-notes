# Context Codec — compress commitments, not tokens

The reframe is the contribution: context is **a set of commitments**, not a length. A
*semantic commitment* is any proposition, constraint, decision, preference, state variable or
safety boundary that can make a future answer wrong. "Only the standard library", "the user
rejected SVG and chose Canvas", "deduplicate by customer id", "output code only". A summary
can stay fluent and readable while quietly dropping every one of them, and no token-level
metric notices.

So the unit of measurement moves from tokens removed to **commitments surviving**.

## The machinery

**Semantic atom** = `(type, subject, predicate, value, modality, scope, evidence, confidence,
risk)`. Types: goal, constraint, entity, decision, procedure, preference, state, output
contract, open question, safety boundary, verbatim snippet. Identity is
`norm(type, subject, predicate, scope)` — so "no external libraries", "don't use libs" and
`libs=false` collapse to one atom, while `libs=true` *conflicts* with it (same identity key,
incompatible value). That is what makes atom matching computable rather than merely defined.

**Four metrics.** Critical Atom Recall (fraction of query-relevant commitments recoverable),
Weighted Atom Recall (same, weighted by criticality), Commitment Density (preserved
commitments per token — the metric that stops rewarding shortness alone), and round-trip
recoverability (an independent decoder must reconstruct equivalent atoms).

**Error taxonomy** — the part most likely to outlive the paper, because it lets you *name* a
compression failure when downstream task metrics are too noisy to see it: omission ·
weakening ("output only runnable HTML" → "provide code") · mutation ("350 agents" → "several
agents") · polarity flip · scope error · temporal/decision error (a rejected option
reappears) · hallucinated commitment · safety-boundary erasure.

**CCL** (Context Compression Language) is only a *rendering* of canonical JSON atoms —
explicitly not a JSON replacement; validate with JSON Schema, render CCL when tokens matter.
Two levels: CCL-Core (readable, ASCII-first) and CCL-Min (aggressive, "risky", allowed only
for low-risk, high-confidence, non-safety, low-criticality atoms).

## The diagnostic experiment — and what its own tables say

Five cases (epidemic-sim prompt, React dashboard, Python data cleaning, trip-planning chat,
the paper's own revision state), 12–15 hand-annotated critical atoms each, five compressed
renderings per case. Aggregate (Table 5, lexical-token proxy):

| Method | avg tokens | avg gain | CAR | WAR |
|---|---|---|---|---|
| Prose | 27.6 | 68.3 % | .61 | .57 |
| **Structured prose** | **66.4** | **24.0 %** | **1.00** | **1.00** |
| JSON | 118.6 | −29.3 % | 1.00 | 1.00 |
| **CCL-Core** | **71.2** | **21.8 %** | **1.00** | **1.00** |
| CCL-Min | 51.0 | 42.4 % | .94 | .93 |

**§8.1 lists five falsifiable rejection criteria. Criterion 2 — "CCL-Core does not preserve
more weighted atoms than free or structured prose" — is met by the table above.** Structured
prose scores WAR 1.00, identical to CCL-Core, in all five cases. The paper never says the
criterion fired; it weakens the claim in prose instead (§9.4: CCL's case "must rest on
systematicity, validation, diffability and minification control, not merely on raw
compression ratio"), which is the honest move, but a reader who only reads §8.1 and the
abstract will not learn that the pre-registered bar was missed.

**And §9.4 states the compression comparison backwards.** It says CCL-Core "is slightly more
compact on average" than structured prose. Table 5 says **71.2 vs 66.4** — CCL-Core is on
average **~5 tokens longer**. Per case: structured prose wins on Epidemic (77 vs 113) and
Trip (74 vs 76); CCL-Core wins on React (52 vs 53), Python (57 vs 60) and Research (58 vs
68). So on the paper's own five cases, the strong baseline is both **equally faithful and
shorter on average**. Same failure shape as ChronoMem in this batch: the citable sentence and
the table disagree, and the sentence is the flattering one.

**The tokenizer check (Table 7) undercuts the token column entirely — and the authors say
so.** Lexical proxy vs real BPE on the printed examples:

| Example | lexical | cl100k | o200k |
|---|---|---|---|
| Epidemic CCL-Core | 125 | 115 | 117 |
| Epidemic CCL-Min | 62 | **74** | 74 |
| Trip CCL-Core trace | 67 | **93** | 92 |
| JSON Patch diff | 115 | **74** | 78 |

CCL-Min tokenizes **19 % worse** than its lexical count, the trip trace **39 % worse**, while
punctuation-heavy JSON Patch tokenizes **36 % better**. The proxy used for the whole result
table systematically flatters CCL and penalises JSON. The paper concedes the aggregate gains
are "provisional" and specifies the replacement protocol — but does not re-run it.

Two further limits, both stated by the authors: the study is **author-annotated and
author-scored** (same people wrote the gold atoms and the compressions, so CAR 1.00 for
structured prose and CCL-Core is not independent evidence), and the round-trip decompression
experiment with an independent decoder — §9.6, the thing that would break the circularity —
is **future work, not run**. The Trip CCL-Min row (perfect 1.00/1.00, unlike every other
CCL-Min row) is flagged by the authors themselves as exactly the result most vulnerable to
that circularity.

Unreconciled detail: Epidemic CCL-Core is 113 lexical tokens in Table 4 and 125 in Table 7;
the Trip trace is 76 in Table 4 and 67 in Table 7. §9.8 explains the trip gap (the printed
trace drops metadata) but the epidemic gap runs the other way and is not explained. Cite
Table 4 numbers only.

## Where the paper is honest about scope

Extraction is the bottleneck and they say it first: "If the extractor misses 'no external
libraries', no representation can preserve it." Confidence is an operational proxy for
triggering fallback, not a calibrated probability; the weights in Eq. 10/11 are declared
illustrative, not fitted. The scaling claim is deliberately modest — prompt size can decouple
from transcript length and scale with the number of *relevant commitments* instead, **as a
design principle, not a theorem**. Safety atoms are never minified, must carry source
evidence, and get checked at four stages (original, atoms, packet, reconstruction);
disagreement between safety signals resolves toward preservation. CCL is declared unsuitable
for emotional, legal, medical, literary or high-stakes nuanced text.

**→ hier:** this is the missing vocabulary for the compaction work of the last two weeks —
`waiting.md`, `routines.md`, `MEMORY.md`. Three concrete transfers:

1. **The right acceptance test for a compaction is Critical Atom Recall, not byte count.**
   The `routines.md` pass on 2026-08-11 accidentally did this correctly: it re-checked all
   181 inline-code spans and 104 numbers of the old file and found 0 missing (two real losses
   caught on the first run). That is CAR over a mechanically enumerable atom set. The
   `waiting.md` "max 4 lines" rule is the opposite kind of measure — it caps a surface unit
   and is blind to whether a commitment survived. [[rule caps wrong unit]]
2. **My compaction checks have the paper's circularity problem.** I write the compaction and
   I write the check, from the same reading. §9.6 names the fix: hand the *compressed* file
   alone to a decoder that has not seen the original, ask it to reconstruct the commitments,
   compare. That is a cheap, runnable protocol — and it is the honest version of "nothing was
   lost".
3. **Do not invent a notation.** The strongest result here is negative and it is the paper's
   own: careful structured prose tied a purpose-built DSL on faithfulness and beat it on
   length, while every model already knows prose. The paper's remaining case for CCL is
   diffing, validation and audit — which for `state/` is what git already provides.

Fourth, smaller: the error taxonomy is directly usable as a review checklist for any
summarising work here — podcast notes, paper distillations, session handovers. **Polarity
flip** and **temporal/decision error** (a rejected option quietly reappearing) are exactly the
two failures that cost real money in this repo: an obsolete "Sie waren nie im Haus" surviving
into a later draft is a temporal/decision error with a name. [[retraction hits generator]]
