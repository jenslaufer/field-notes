### Agent businesses & monetization
- **2026-08-21** · [Grok Bot: How to Build a 1-Person $10M Company](2026-08-21-grok-bot-agent-team-newsletter-billy-howell.md) — Billy Howell runs a 6,000-sub local newsletter on a Grok Bot agent team after his intern left. Payload is tool-independent: **build team wk 1 → execute with no tinkering wk 2 → hire/fire wk 3 → automate wk 4**. Best operational idea: **earn the right to create an agent** — have the chief of staff do the task once, review it, *then* spawn the specialist. One project per account (token debt + context bleed); *"you're the person that has to make the decision, not the agent"* (3 weeks lost to Notion-vs-Sheets); five-line agent briefs rolling up to *"what's shipped, what's stuck, and what needs you"*; **adversarial sub-agent panel, three rounds, 50 % → 90 % done**; push deterministic volume off the expensive agent (make.com) but only **after** it ran manually. Shapes: local/niche newsletter, Astro+Cloudflare directory, Shopify. Grok Bot = xAI, beta 11.08.2026, cloud VM per agent, ~200–300 USD/mo (price unconfirmed)
- **2026-08-12** · [My top secrets to running an AI Agent Workforce](2026-08-12-ai-agent-workforce-allie-k-miller.md) — Allie K. Miller (ex-AWS/IBM) on **34 agents**: 1 chief of staff + 6 directors, all named after *Friends* characters. **"Managing agents" is the wrong word** — you set the infrastructure and wait for escalations. The best prompt she has is three words (*do smart things*) on top of full context access + quarterly **goals** review; scope widened, risk tier unchanged. Don't staff 2015 job titles: the roles worth hiring at zero marginal cost are **Phoebe** (asks "how do we 10× this?") and **Toby** (watches the workforce, logs friction and missing access). Ramp: one agent → one proactive agent → two agents → workforce; sub-agents on Haiku/Sonnet, *"not everything needs opus"*. Two opportunities: **AI as a watchdog with insight-to-action** (*"dashboards are dumb"*) and **build the factory, not the thing**. SaaS apocalypse is slower than predicted — bandwidth, liability (*"who's liable now?"*), lab-access lag, maintenance

### Using the models well
- **2026-08-19** · [How I Use Skills + AI Agents to Run My Life](2026-08-19-skills-plugins-team-distribution-remy.md) — Remy on **distributing skills**: a skill on one laptop is a fraction of the same skill in a repo everyone installs. *"skills are literally just SOPs for AI"*; the bookshelf picture (spine = name+description, always loaded; body = opened on demand). The **"Microsoft Word era of skills"** — zip-on-Slack and Drive/Dropbox/Obsidian both break; the fix is **GitHub repo → plugin marketplace → `/plugin` add marketplace, auto-update ON**, foldered by department as access control. Works in Codex too. Second private repo for personal SOPs — motivated by Claude deleting his 150-skill folder with no backups. Two things worth copying outright: a **self-improvement block at the bottom of every SKILL.md** (did a step fail, did the user correct you, did you learn something a future run needs) and a **usage hook** to find skills to cull. *"thin agents, thick skills"*
- **2026-08-17** · [How to use Claude Code better than 99% of People](2026-08-17-claude-code-ai-employee-nine-pieces.md) — Solo, Anthropic-sponsored: give Claude the **nine things you would give a new hire** — workspace, memory, brief (plan mode), ticket, eyes, review, schedule, permissions, skills/connectors/hooks — plus a seven-day plan. Repo layout `/app /context /customers /specs /demos /routines` + `CLAUDE.md` / `roadmap.md` / `review.md`. *"one task, one finish line and one reviewable change"*. **Measured against Otto: 8 of 9 pieces already exist here, several further** (44 routine lines vs his two routines; a memory eviction policy he has none of). **The two gaps are `/customers` and `review.md`** — and five of five extension repos have no customers folder, while 16 FinGrab store reviews and a `unused` cancellation after 6:43 sit in no file an agent can read. Careful: YouTube currently titles it "Claude Code New Features, Explained" (A/B test — go by `videoId`), and the "99%" is never said in the episode
- **2026-08-03** · [Graph Engineering Clearly Explained](2026-08-03-graph-engineering-clearly-explained.md) — **(from the audio transcript, 03.08.)** prompt eng. = better question, context eng. = better information, **graph eng. = designing the work around the AI**: jobs + arrows + shared state, so it stops living in one giant chat. Knowledge graph (how information connects) vs agent graph (how work moves) — this is about agent graphs. The diamond: planner → parallel researchers → **skeptic** → merge → human gate, worked end-to-end on "should I launch AI bookkeeping for Shopify merchants". Three levels: manual lanes on a whiteboard → a repo where each step writes `plan.md`/`review.md`/`recommendation.md` → LangGraph/AutoGen GraphFlow/n8n. Anti-pattern: more agents = more noise; aim for the **smallest** graph that raises quality, delete the fake waiting, put the human gate where mistakes are expensive. Sleeper point (absent from the show notes): graphs **produce memory**, and that context is the moat
